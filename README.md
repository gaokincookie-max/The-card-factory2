# Factory Card Game v2.2 — 基盤整理 第1段階

v2.1 の画面・工場・戦闘を保持しながら、**追加機能を作りやすくするための段階的リファクタリング**を開始した版です。全面的なオンライン対応やUI再構築はまだ完了していません。

## 起動

- GitHub Pages: フォルダ内容をリポジトリのルートに置き、Pages で公開
- ローカル: `python -m http.server 8000` を起動し `http://localhost:8000/` を開く（単にHTMLをダブルクリックすると fetch が制限されることがあります）
- テスト: Node.js で `npm test` / `npm run check`（追加パッケージ不要）

## 開発を再開するなら

1. `ARCHITECTURE.md`：ソースコードの責務と依存関係
2. `GAME_RULES.md`：今の仕様と未実装・要検証事項
3. `BALANCING.md`：数値調整の正しい変更箇所
4. `COMMAND_API.md`：UI/CPU/将来サーバー用の共通操作形式
5. `NETWORK_DESIGN.md`：オンライン化に必要な追加設計
6. `CHANGELOG.md`：今回の変更、今後の移行順序

## 特記事項

- ゲームバランスは変更しない方針。数値を移した箇所も元と同じ値です。
- 古いテストには廃止済み仕様を前提とするものがあります。`npm test` は現行仕様に対応したテストを実行します。
- 将来は独立したタイトル画面・モード選択・設定画面を用意する予定。現時点で仮のメニュー画面をゲームに組み込んでいません。

## v2.3 Phase 2 の追加情報
- UI経由の主要工場操作を共通命令APIへ移行（詳細: `MIGRATION_STATUS.md`）。
- 決定的乱数: `src/random.js`、保存用境界: `src/match-state.js`、画面に依存しない進行: `src/match-runner.js`。
- 状態保存の形式と制限: `SNAPSHOT_FORMAT.md`。
- `npm test` / `npm run check` を実行してください（Node.jsが必要）。
- 正式なメニュー画面、CPU工場、オンライン同期、実ブラウザの全操作テストは今後の工程です。

## v2.4 の変更（基盤整理 Phase 3）
戦闘UIの操作が共通命令APIを経由するようになりました。変更範囲と今後の課題は `MIGRATION_STATUS.md`、APIの使い方は `COMMAND_API.md` を参照してください。`npm run check && npm test` でテストできます。バランス値の全面分離・UI/エンジンの完全分離・オンライン対戦はまだ未完了です。

## v2.5 Phase 4
`src/battle.js` と `src/battle-ui.js` を分割し、補助効果の主要数値を `src/balance-config.js` に集約しました。変更範囲・未移行箇所は `PHASE4_NOTES.md` を参照してください。

## v2.6 Phase 5
採掘・倉庫・ベルト・加工と強化の共通調整値を `src/factory-economy-config.js` に分離しました。変更箇所の案内と残課題は `PHASE5_NOTES.md` を参照してください。`npm test` にv2.5との工場状態比較テストを追加しています。

## v2.7 Phase 6
ユニット固有能力の数値設定を `src/balance-config.js` に集約し、戦闘のゴールデン回帰テストを追加しました。詳細は `PHASE6_NOTES.md`。起動方法は従来どおりです。

## v2.8 Phase 7：基盤整理の区切り
工場の時間更新処理を `src/factory-simulation.js` に分離し、工場の入出力矢印表示の無駄な再作成を削減しました。`npm run bench` で工場計算の負荷を測定できます。**計算速度の有意な改善は計測されていません。** 移行状況と残る技術的課題は `PHASE7_NOTES.md` を参照してください。


## v2.9 メインメニュー・プロトタイプ
`index.html` を開くか静的サーバーでホストすると、メインメニューから開始します。
左の4項目とサブ選択、中央情報パネル、右フレンド、右上設定が利用できます。
現在プレイできるのは「戦う」→「CPU対戦」です。恒常工場などの画面は開発予定の案内のみです。
詳細は `MENU_DESIGN.md`。
