# v4.7.36 β1 — Tutorial reliability

## Changes
- Recipe success uses exact manual recipe ID, not boolean/string comparison.
- Tutorial command policy guards building, removal, recipe, belt, unit and support actions before mutation; normal CPU and online paths are not gated. Free exercise is unrestricted.
- Material-use completion uses successful PLAY_CARD command, independent of hand refill. Production waits check current hand; temporary warehouse filtering is allowed in recovery and must be restored to unit mode.
- Belt checks include the preceding join and terminal direction, with retry from the start if rejected. Pending placement and opened facility are read from actual app UI state.
- Tutorial combat callback counts assault hits without relying on fixed damage; pulse runs per simulation substep. Preparation hold uses battle.ready minus five seconds.
- Guided construction selects the correct facility button. Restart clears factory selection, modal, and card detail. Completion flag is retained after exit.
- Test script includes all new chapter, warehouse and controller tests. The controller integration test uses simulated DOM/input and real command/engine/controller code; it is not a browser interaction test.

## Verification / limits
- `npm run check` and `npm run test:tutorial`: pass (25/25).
- Broad direct file-by-file test audit includes historical scripts and current test files; 31/41 pass, 10 fail. See baseline comparison in delivery notes.
- Chromium navigation to local server is blocked by environment policy. No actual browser/iPhone interaction test. Full UI spotlight/drag guidance, all pathological inventory recovery, text cleanup, and remaining legacy regression failures are deferred. This is a beta, not a release certification.
