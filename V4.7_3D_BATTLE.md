# v4.7 3D battle display (experimental)

- Adds `src/battle-3d.js`, a standalone Three.js/WebGL scene for the 20 battle slots.
- Cards are flat 5:7 planes laid on one table. One local camera provides perspective; the near side is always the local player's team.
- Ally/enemy colors are display-only. The existing command, battle, factory, network, hand and detail systems are unchanged.
- A 3D slot click is forwarded to the existing HTML slot handler. Unit hand drops raycast against 3D planes; other support-card interactions use the existing handlers.
- Registered images from `src/battle-art.js` render on card textures after loading. Fallback card texture is generated if artwork is absent.
- Three.js 0.180.0 loads from jsDelivr at runtime. If offline, blocked by CSP, or WebGL unavailable, the original HTML battlefield remains in operation. To ship offline, vendor the pinned `three.module.js` and change `THREE_URL` in `src/battle-3d.js` to its local path.
- Only the visual board and card planes are 3D. HP/card details/hand remain HTML.
- Existing full `npm test` is intermittently blocked by `test_v16.mjs` using fixed cells where v4.4 randomly generates resource zones; not changed in this release.
- This revision passes `npm run check`, `tests/battle-perspective.test.mjs`, `tests/battle-boundary.test.mjs`, `tests/duel-match.test.mjs`. Browser/GPU and multi-device integration tests remain necessary.
