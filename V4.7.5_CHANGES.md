# v4.7.5 — Mobile landscape presentation & balance

- Portrait phones are presented with the whole page rotated 90° (CSS display rotation, not OS orientation lock). Applies to menu, factory and battle.
- The Three.js raycaster maps coordinates for the rotated canvas; touch gesture handling recognizes portrait-held landscape display.
- Preparation length: **300 seconds**; headquarters max and initial HP: **10,000**. Both CPU and online matches share `BATTLE_RULES`.
- Updated visible countdown copy in menus and online lobby.

## Friend match 3D audit

`createBattle3D` reuses the same board scene per client. `getMyTeam()` selects the near team regardless of player slot (team 0 or 1). Slot metadata keeps the authoritative `(team,col,row)` and is handed back unchanged on click. Existing drag commands target `myTeam()`, so the other player cannot accidentally deploy into the wrong faction. Verified through duel and online-session tests, plus rules/slot-mapping static assertions; **not validated on two physical devices**.

## Known issues / testing guidance

- Mobile Safari cannot reliably force device orientation in a normal web page. This rotates page content while the device remains in portrait. Browser chrome and keyboard won't rotate.
- Check phone portrait hold: menu, factory, battle, tap and drag, 3D slot targeting, and text input overlays. In the landscape-held orientation, no CSS rotation is applied.
- Legacy `test_v17_audit.mjs` and other old tests assume a 120-second preparation period. They need expectation updates before the whole historical suite passes. The targeted new test and online tests pass.
